# 目的
このスキルは、Astroプロジェクト（またはその他のフロントエンドプロジェクト）において、単に機能するUIではなく、「本質的なユーザビリティ」と「ブランド特有の独自性（脱・陳腐化）」を両立した高いクオリティのデザインシステムが運用されているかをレビューし、改善を促すために使用します。

# 実行手順

## 1. デザインシステムの統一性の確認
コードベース内（`src/` 配下や設定ファイル）を検索し、デザインのルールがハードコードされずに一元管理されているかをチェックします。
- **デザイントークン**: カラーパレット、タイポグラフィ、スペーシング、コンポーネントの装飾（角丸、シャドウなど）が `tailwind.config.mjs` または CSS変数（カスタムプロパティ）に定義されているか。
- **コンポーネントの再利用**: 同じような見た目のボタンやカードが複数箇所で都度スタイリング（ハードコード）されていないか。[DRY原則違反の指摘]
- **一貫性と標準化**: サイト全体でフォントウェイト階層、余白の法則（例: 4px/8pxベースなどのスペーシングルール）が統一的に使われているか。

## 2. ユーザビリティ10原則 (ヤコブ・ニールセン基準) の確認
UIの実装（JSX/Astro/HTML）を読み取り、ユーザーが直感的に操作できる状態になっているかを評価します。特に以下の点に注目します。
- **システム状態の可視性**: ボタンのホバー (Hover) やアクティブ (Active)、フォーカス (Focus) 状態のスタイルが明示されているか。ローディングやスケルトンスクリーンの考慮があるか。
- **エラーの予防と親切なメッセージ**: フォームの入力項目に適切なプレースホルダーや、クライアントサイドでのバリデーション表示が備わっているか。
- **簡単な復帰**: グローバルナビゲーションやパンくずリストが存在し、ユーザーが「現在地」を見失わない構造になっているか。
- **柔軟性と効率性**: 適切なアクセシビリティ属性 (`aria-*` や `role`) が付与され、キーボード操作やスクリーンリーダーに配慮されているか。

## 3. 独自性の評価（脱・俗物的ルックの検証）
機能的であっても、「どこかで見たようなテンプレート風」の退屈なデザインになっていないかを批評し、美学的な向上を提案します。
- **依存の排除**: Tailwindの標準カラー（例: `bg-blue-500`）をそのまま使用せず、ブランド特有のカラーパレット（HSL調整やグラデーションなど）が適用されているか。
- **タイポグラフィの美学**: システムフォントの羅列ではなく、明確な意図を持ったWebフォントの使用や、行間 (leading)・文字間 (tracking) の調整などの「文字組みの美しさ」が実装されているか。
- **マイクロインタラクションとダイナミズム**: 単調な状態遷移ではなく、適切なトランジション（`transition-all duration-300 ease-in-out` など）や、スクロールに合わせた控えめなアニメーション（Framer MotionやCSSアニメーション）が存在するか。
- **空間の演出**: 一般的な「詰め込みすぎた」レイアウトではなく、十分な余白（Whitespace）を使った高級感（プレミアム感）やメリハリがあるか。

## 4. レポートの生成と改善案の提示
調査が完了したら、アーティファクト（Markdown形式など）を使用して、ユーザーにレビュー結果を報告します。
報告時には以下の項目を含めてください。

### レポートの構成案
1. **総評・デザインインデックス**: 現在の統一性、ユーザビリティ、美学的独自性のスコアまたは評価サマリー。
2. **デザインシステムの破綻・DRY原則違反箇所**: ハードコードされたスタイルや、統一ルールから外れているコンポーネントとその修正案。
3. **ユーザビリティの課題**: エラーやホバーフィードバックの欠如などの指摘と、アクセシビリティ改善のためのコード提案。
4. **俗物的ルックからの脱却（独自性の向上案）**: 単調なデザインに陥っている箇所を指摘し、「よりプレミアムで印象的なUI」にするための具体的なスタイリングやアニメーションのコード例を提示すること。
5. **Next Action**: 修正すべきタスクの優先順位リスト。

# 留意事項
- 「もっと良くできる」という観点で、妥協のない高い水準のデザイン（モダン・リッチ・ダイナミック）を求める姿勢でレビューを行うこと。
- 問題の指摘には、必ずTailwind CSSやAstroを用いた具体的な**「改善コード（修正例）」**をセットで示すこと。
- 新しいCSSクラスを追加する場合は、既存のデザインシステムとの整合性を保つこと。
